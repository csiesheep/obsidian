# [開發筆記] 一個網頁菜鳥，用 AI 幫《山中小屋》做了一塊音效板 —— 順便把小孩拉下水

先招認一件事：我幾乎沒什麼網頁開發的經驗。

CSS 對我來說一直是個玄學，flex 到底往哪邊 flex，我大概 debug 過的時間比寫的時間還長 orz。

那，一個不太會做網頁的人，為什麼會生出一個網站？
而且還是一塊《山中小屋》(Betrayal at House on the Hill) 的**音效板**？

線上玩玩看 👉 [games.csiesheep.com/betrayal_sound_board](https://games.csiesheep.com/betrayal_sound_board/)

說穿了，就三個理由。

---

## 理由一：我想拿 AI 開發練手，而「不會」剛好是重點

這幾年 AI 寫程式很紅。紅到我忍不住想問一句——真的嗎？

我不想只是看別人的 demo 點頭。
我的老毛病是，聽到一個很紅的方法，一定要拿自己當白老鼠試一遍，有用沒用都照實記下來（這招從我當年寫〈顏色管理法〉試自己的習慣就是這樣，結果那次還失敗了，哈）。

而「我不太會網頁」這件事，不是缺點，是**實驗設計**。

最大的風險來自無知——我對前端的無知夠深，正好拿來量一件事：
**AI 到底能不能把一個人扛過他原本不熟的領域？**

我守住我唯一相信的一條老規矩：不管 AI 幫我吐出多漂亮的 code，**我一定要看得懂、測得過**，不確定的邊界我自己盯。AI 是拿來消滅「未知」的，不是拿來製造「我不知道自己在跑什麼」的。

實測結論先講：能。而且比我想的遠。
我甚至反過來養了三隻小幫手——三個 Claude Code 的自訂 skill：`find-sound-effect`（找授權乾淨的音效）、`create-image`（手繪 SVG 風格 icon）、`add-element`（把前兩隻串起來、一鍵上架）。

到今天，這塊板子上有 **158 個元素**，分六大類：道具、武器、怪物、房間、凶兆、事件。
一開始是一個一個手工加，加到手軟；後來變成「跟小幫手說一聲，怪物就上架了」。

這一段，就是我最想練的東西——不是寫網頁，是**怎麼把一件重複的事，變成一條產線**。

## 理由二：我是桌遊控，而《山中小屋》是我的本命

會做這個，最誠實的動機其實很簡單：我很愛這款遊戲。

《山中小屋》最迷人的地方，是前半段大家一起探索、氣氛越來越不對勁，然後某一刻「兆」湊齊，**叛徒翻面**，整張桌子的空氣瞬間變了。

那個氛圍，值得配音。

所以這塊板子不是什麼大東西，就是一個念頭：
> 「我想擁有能力和熱情，做出真的能讓人生活更方便（或更好玩）的東西。」

這句話是我很久以前讀 Woz 自傳（《iWoz》）記下來的，一直放在心裡。
這次它落地成——當家裡開《山中小屋》，我按一個鍵，班西的尖叫、電鋸的轟鳴、老房子的低鳴就出來了。

技術上其實很樸素：純 HTML / CSS / vanilla JS + Web Audio，沒有後端，丟在 Cloudflare 上。
我還把實體那 43 張事件卡一張一張抄進資料裡（是的，用手抄的，桌遊控的浪漫 XD）。

不華麗。但它讓我最愛的那款遊戲，多了一層我一直想要的東西。

## 理由三：我想讓小孩跟我一起做

這是我私心最重、也最捨不得省的一個理由。

我的小孩會長大在一個「創意落地成本越來越低」的世界。
我不確定十年後的工具長怎樣（真的不確定），但我幾乎可以確定一件事：**會不會把腦袋裡的東西做出來，會是很關鍵的能力。**

所以我沒有把他們當觀眾。
我讓他們一起：這隻怪物該配什麼聲音？這個 icon 畫成這樣好不好看？
他們出點子，我們一起跟 AI 講，然後——**東西真的出現在螢幕上**。

那個「欸，我想的東西變成真的了！」的表情，我覺得比任何一堂程式課都值得。

我不是在教他們寫 code。
我是想讓他們早一點體會：**一個念頭，是可以被實現的。** 而且門檻，比我小時候低太多了。

（順帶一提，這大概也是一種偷渡的「talent stacking」——桌遊 + 一點點技術 + 陪小孩，各自不頂尖，疊在一起就變成只有我們家會做的東西。）

---

## 目前為止的誠實結算

- 網頁菜鳥 + AI，一個多禮拜生出一塊上線的板子。可行，超乎預期。
- 但我沒有假裝一路順風：CSS 還是折磨我，SEO、AdSense、Cloudflare 的坑一個接一個，`/` 一開始還很沒禮貌地回 404（已修 orz）。
- 最大的收穫其實不是那個網站，是那三隻 skill——把「加一個元素」從勞力變成產線。這套「先減少不確定、動手做個小東西來學」的思路，比網站本身更值得留下來。

工具會過時。
「一個念頭可以被做出來」這件事，不會。
