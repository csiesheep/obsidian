## 2026 補記

這篇在介紹羊羊是怎麼生出來的~
十七年後回頭看，最有感的是：當年羊羊靠的那些東西，幾乎都換了一輪 orz

就照原文的順序，一個一個點名吧~

### 1. plurk api

當年用的是非官方的 rlplurkapi，放在 Google Code 上。
結果 Google Code 自己先收攤了：2015 年 3 月 12 日宣布關閉、停止建立新專案，2016 年 1 月 25 日正式關站。
噗浪則是在 2009 年 12 月 4 日開放了官方 API，也就是這篇寫完大約五個月後。
後來的 API 2.0 改用 OAuth 1.0a，程式不用再拿著帳號密碼去登入了。

### 2. simplejson

Python 2.6（2008 年 10 月 1 日釋出）起，標準函式庫就有 json 模組。
現在寫程式，大概不會再為了解析 JSON 另外裝一個套件了~

### 3. Yahoo 知識+ api

這個最痛。羊羊的「知識」全部來自知識+。
Yahoo 奇摩知識+ 在 2021 年 4 月 20 日（美東時間）起改成唯讀，5 月 4 日正式結束服務；使用者可以申請下載自己的內容到 6 月 30 日，之後資料就刪除了。
也就是說，就算今天把羊羊的程式翻出來，它也已經沒有後盾了。

### 4. 羊羊的家：Andlinux

當年把 Ubuntu 當成一個軟體裝在 Windows 下，感覺很新鮮。
2016 年微軟在 Build 大會發表 Windows Subsystem for Linux（WSL），把這件事變成作業系統內建的功能；2025 年 WSL 還開源了。

### 5. crontab 每 20 秒叫羊羊起床

當年的做法是一直「輪詢」：每次起床只看最新的 20 筆，所以朋友一多就會漏回，又因為延遲而重複回答。
現在噗浪 API 2.0 的文件裡，建議用 `/APP/Polling/getPlurks` 拿新的噗，另外還有即時的 comet channel，文件直接寫說這比輪詢更有效率、也更快。
現在回頭看，羊羊那些重複回答，有一部分其實是架構造成的，不全是羊羊笨 XD

### 現在回頭看

把原文列的 5 樣東西對一下：

- rlplurkapi 所在的 Google Code、還有知識+：已經關站。
- simplejson 和 Andlinux：都有了內建的替代品。
- crontab 輪詢：有了更好的做法。

真正還在的，大概只有噗浪本身。

我覺得這篇給我最大的提醒是：
**程式寫得再好，也活不過它依賴的平台。**

如果現在再做一隻羊羊，我大概會先問：
這些依賴裡，哪一個最可能先消失?消失了，我能不能搬家?
這大概也是「先減少不確定的因素」吧~ :p
