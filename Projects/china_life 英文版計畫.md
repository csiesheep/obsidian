# 生在中國｜英文版（Born in China）實作計畫

> [!info] 一句話
> 引擎不動，在顯示層加一層語言。中文版的模擬、統計、黃金測試都不受影響。英文版放在 `/china_life/en/`，和中文版共用同一套程式。工作量比 [[china_life 簡體與英文版推廣]] 估的大：要翻的字約 **30 萬**（不是 19 萬），而且有三個地方不能只靠翻譯（見 §1）。估計 peer 工作 **2.5–3 週**，其中一半是每日句（約 9.9 萬字）的翻譯與抽審。

推廣（Reddit、Show HN、短影音）照 [[china_life 簡體與英文版推廣]] §2，這份只談怎麼做出來。

除了建置產生的時代頁，真正要寫成英文的約 **21 萬中文字**，大約是 13–15 萬英文字。

## 1. 三個不能只靠翻譯的地方

1. **中文詞被當成 ID。** 身分（士農工商兵賤籍官盜）、死因（夭折、瘟疫…）、科舉級別、行業、豐歉、每日句主題都是中文字串，引擎、資料檔、網址重現都靠它們。
   → **ID 一律不改**，另建「ID → 英文顯示名」對照表。引擎與黃金測試完全不碰。
2. **程式會解析中文。** 故事從 `。`、第一個 `（` 切主題，節日用中文正則判斷，引擎從 `periods.csv` 的纏足欄文字解析出比例。
   → 解析一律跑在中文原文上；英文只在**最後顯示**時換上去。纏足欄維持中文給引擎讀，英文另開欄。
3. **文法寫死在程式裡。** `src/story.js`（生平、墓誌銘）、`calendar.js`（年號紀年）、`share.js`（分享卡）、`main.js`（出生句）都是用 `歲`、`個孩子`、`朝` 拼出來的。
   → **另寫一套英文產生器**，不是翻模板：處理單複數、a/an、0 歲與 1 歲、序數、冠詞。

## 2. 架構決定（建議）

- **網址**：`/china_life/en/`（`en/index.html`、`en/stats.html`、`en/codex.html`、`en/era/*.html`），`hreflang` 兩邊互指。語言由頁面的 `<html lang>` 決定，不用 `?lang=`，對 SEO 比較好，分享連結也不會失去語言。
- **語言層**：新增 `src/i18n.js`，提供 `t(key, vars)`、`label(kind, id)`（ID → 顯示名）、`fmtYear()`、`fmtAge()`。中文走原本的表；英文表放 `data/text/en/`，檔名與 key 和中文**一一對應**。
- **紀年**：英文寫作 `1689 (Kangxi 28, Qing)`，公元前寫作 `206 BC (Han)`；干支只在中文版顯示。
- **人名與地名**：漢語拼音，不標聲調（`Chen Guizhen`、`Jinan`）。761 個名字、140 個姓、地名做一張一次性對照表（AI 產生，writer 抽審），**不加套件**。
- **病名**：古名意譯，加今名，例如 `consumption (tuberculosis)`。
- **分享卡**：英文用另一套排版，依空白斷行，標題與印章不用全形空白拆字，字型用系統襯線字（Georgia／Times）。
- **版面**：用 `:lang(en)` 覆寫字距；直排（`vertical-rl`）的地方改橫排；`em` 寬度在英文版重新量。
- **眾生簿**：兩種語言共用同一池人生（同一套 ID），上傳時加一欄 `lang`，方便以後分開看。
- **SEO**：`data/text/en/seo.js`；`og:locale en_US`、`inLanguage en`；英文 sitemap 條目；英文 OG 圖。
- **中文版保證不變**：中文頁輸出逐位元組不變（現有 harness 全綠＋`build_era --check`）。

## 4. 驗收（orchestrator 先寫，peer 交付前就要能跑）

- **完整**：每個中文 key 都有英文 key，佔位符（`{age}`、`{place}`…）兩邊一致；多出或缺少都紅。
- **英文頁沒有中文**：`/en/` 底下所有頁面跑 50 個 seed 走完一生，畫面上不得出現 CJK 字（白名單只有印章「生在中國」與拼音附的漢字註解，如果採用）。
- **中文版不變**：中文頁 harness 全綠，`build_era --check`、黃金測試不變。
- **文法**：0 歲、1 歲、2 歲、1 個孩子、2 個孩子、a/an、公元前年份、跨朝代年號都有測試列。
- **版面**：360 寬下英文最長的抉擇、按鈕、統計標籤不溢出（沿用 `acc_textfit` 的量法）；分享卡每行在 960px 內，hook 最多 3 行。
- **證偽**：拿掉一個英文 key → 完整性列紅；英文產生器回傳中文 → 「沒有中文」列紅。

## 5. 要 owner 決定的事

1. **網址**：`/china_life/en/`（建議）還是 `?lang=en`？
2. **名字**：英文名 **Born in China**（大廳磚已經這樣寫）？
3. **拼音**：不標聲調（建議）、標聲調，還是用威妥瑪拼法？
4. **紀年**：`1689 (Kangxi 28, Qing)`（建議），還是只寫公元年？
5. **每日句**：9.9 萬字全翻（建議，品質一致），還是先翻 40% 上線、其餘之後補？先上線可以省約 3 天。
6. **開發日誌**：不翻，英文版連到中文版（建議）？
7. **誰讀英文成品**：P7 要有人讀 20 個一生全文。你自己讀，還是找一位英文母語者？
8. **自動切換**：第一次造訪時，依瀏覽器語言顯示一行「Read in English?」提示（建議，不自動跳轉），還是自動跳轉？
9. **TapTap App**：App 依手機語言開 `/en/` 或中文版，還是固定開中文版？（改了要重建 APK 送審）

## 6. 風險

- **翻譯品質**：AI 初稿＋writer 每檔抽審 10%，錯誤率高的整檔重審；史實與語氣以詞表為準。
- **文化說明**：英文讀者不懂科舉、賤籍、纏足。第一次出現時加一行可點開的小註；時代頁的導讀負責講背景。
- **敏感內容**：纏足、饑荒、1949 年後的內容照中文版忠實翻譯，不加料、不刪減。
- **維護成本**：之後每加一句中文都要有英文，「完整」驗收會擋下沒翻的。peer 的派工單要寫明「中英一起交」。
