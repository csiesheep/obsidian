## 2. 內容格式和主場

| 內容 | 是什麼 | 主場 | 也放 | 不放 |
|---|---|---|---|---|
| **Reel full** | 整本漫畫 30 多格照閱讀順序推鏡，加音效和原創配樂，約 60 到 100 秒；之後加配音 | IG Reels | YouTube Shorts、TikTok、FB 粉專（自動同步） | Pinterest |
| **漫畫輪播** | 封面、每一頁、結尾卡，3:4，最多 20 張 | IG | FB 粉專（自動同步）；Pinterest 發文日一起釘封面加前 3 頁，連到 IG | Threads 只放一格 |
| **文字故事** | 500 字鉤子加全文 | Threads：三則一串（鉤子加一格圖、全文附件、IG 連結） | 第 5 週後 FB 粉專貼全文、FB 社團 | IG |
| **預告 Reel A、B** | 同一本挑兩組不同的三格當開頭，15 秒 | Reel full 做好前：A 當正式 Reel 發 IG、YouTube、TikTok；做好後 A、B 都改成 IG 試用 Reels（只給非追蹤者看） | | |
| **一句話鬼故事** | 一到兩句，最後一個詞翻轉 | Threads 每天 1 句 | IG 一句話 Reel 每週 2 支，YouTube、TikTok 同一支 | |
| **互動** | 接一句、看圖猜、投票 | Threads 每週 3 到 4 則 | IG 限動投票 | |
| **第 0 首自介** | 5 張卡 | IG 釘選（已發） | Threads 釘選（還沒發）、FB 粉專手動貼 | |

為什麼 Reel full 是主力：IG 對非追蹤者最看重觀看時間和私訊分享，100 秒的完整故事兩項都比 15 秒預告強；預告的終點是「去主頁看漫畫」要多點兩次，完整版的終點是「追蹤看下一首」；鬼故事最會被轉傳的是看到結局那一刻，預告沒有結局。它也是 YouTube 分潤唯一能累積的格式。

## 6. 工具（照順序）

1. **固定畫風**（第 1 週）：從現有五本挑 3 個方向給擁有者選一個，之後每本不再選畫風。
2. **manga.py reel full**（第 2 週）：照 board.json 的閱讀順序一格一格推鏡，2 倍解析度重繪頁面再切格；程式合成音效（心跳、嗡鳴、監視器、點滴、開門、驚嚇重擊），每格一份音效表 json 可手改；配樂用本機 ACE-Step 1.5 產生幾首品牌固定曲重用；ffmpeg 混音。估半天到一天。
3. **manga.py --dest**（第 2 週）：export 和 reel 直接輸出到故事資料夾的 posts/、reels/<版本>/。
4. **export --pinterest**（第 2 週）：1000×1500 釘圖加標題說明。
5. **週報**（第 2 週）：從成效表算指標。
6. **配音**（第 10 週）：Azure zh-TW 或擁有者自己錄；配音稿從 board.json 的旁白和對白自動抽。
7. **合集長片**（Reel full 做好後的下一週）：`reel weekly`，當週 Reel full 串成一支加片頭、字卡、片尾；擁有者 2026-10-19 要求每週固定出。
