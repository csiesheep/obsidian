# 增量遊戲點子

網頁版優先。參考作品：Bills Must Be Paid、Bottle Flip Inc、Dirt Clicker。

---

## 一、三款參考作品拆解

### Bills Must Be Paid

> Rike Games，Unity WebGL，CrazyGames + Steam，2026

主動點擊型增量遊戲，靠砸存錢筒來繳帳單。

- 砸擊消耗**體力**，手累了這一輪就結束 → 天然的 run-based 結構
- 帳單有**到期日**；不繳，討債的會從之後所有收入抽成
- 豬公掉**隨機戰利品**
- 收集系統：豬公、鎚子、硬幣、戒指、手環
- **最關鍵的設計**：錢有兩個互相衝突的用途——付下一張帳單 vs. 在後面的豬公變硬之前先強化 build
- 高利貸角色，每日抽成總額可能是原始借款的數倍
- **破產 = Prestige 重置**，換 Legacy Points

### Bottle Flip Inc

> Gamechill，約 4 小時短篇

- 翻瓶賺錢 → 買「幫手之手」自動化
- 從瓶子取下**瓶蓋**當第二貨幣，餵養技能樹
- 解鎖新瓶子種類 = 內容變化
- 能力把單純翻瓶變成**華麗場面**
- 一個動詞、一個畫面、明確的結局

### Dirt Clicker

> Sailing Bears

- 從一支湯匙和一小塊泥土開始
- 每挖一次：更多泥土 → 新工具 → 新幫手 → 更大技能樹 → **新地層**
- 幫手有個性：蘑菇夥伴、泥土魔像、德魯伊
- 挖出寶物變賣、稀有拼圖碎片、遺物
- **續探 vs. 下潛**的抉擇
- 40+ 物品、能破壞平衡的法術、能看出誰在偷懶的統計頁

### 共通骨架（值得偷走）

| 層次 | 內容 |
|---|---|
| 核心動詞 | 一個手感好、回饋足的動作（砸 / 翻 / 挖） |
| 軟貨幣 | 持續產出，花在會被通膨掉的升級上 |
| 硬貨幣 | 瓶蓋、Legacy Points——重置後保留，餵養技能樹 |
| 自動化 | 有名字、有個性的幫手 |
| 進度軸 | 看得見的空間推進（深度、帳單週期、距離） |
| 張力 | 逼你取捨的限制器（體力、期限、續探 vs 下潛） |
| 收集 | 掉寶與稀有度，獨立於數字線之外的第二獎勵管道 |
| 結局 | 三款都很短。**2–6 小時走到真正結局，遠勝無限刷** |

## 二、技術規劃（通用）

**技術選型**

- Vite + TypeScript
- UI 用純 DOM/CSS；核心動詞若是物理性的才開一個 `<canvas>`
- 在 UI 真的需要之前**別上 React**——增量遊戲不斷重繪，60fps ticker 上做 DOM diffing 是自找麻煩
- 數字超過約 `1e308` 再引入 `break_infinity.js`
- 真的需要物理才用 `matter-js`

**架構原則**

- 單一個可序列化的 `GameState`。無法 `JSON.stringify` 的東西不該進 state
- 固定時間步 tick（每秒 20 次）與 render 解耦，累積剩餘 dt，避免背景分頁掉進度
- 所有升級／幫手／地層／物品都是**資料**（`content.ts`，純物件 + 成本公式函式）。絕不寫死進邏輯——這決定調平衡是 20 分鐘還是一次重構
- 存檔：每 15 秒 + `visibilitychange` 寫 `localStorage`
- 離線收益 = `Date.now() - lastSave`，設上限（2–8 小時），通常 50% 效率結算
- 成本曲線：`cost = base * growth^owned`，growth 1.07–1.15
- 產出：同層級相加，跨層級相乘

**里程碑**

| # | 時程 | 內容 |
|---|---|---|
| 1 | 第 1–2 天 | 只做動詞。點擊 → 數字上升 + 手感（粒子、震屏、音效、數字彈出）。不好玩就換動詞 |
| 2 | 第 1 週 | 6–8 個升級、存讀檔、成本曲線 |
| 3 | 第 2 週 | 自動化層。**遊戲開始自己跑的那一刻就是鉤子** |
| 4 | 第 3 週 | 進度軸（地層／週期）+ 張力機制 |
| 5 | 第 4 週 | Prestige + 技能樹 + 硬貨幣 |
| 6 | 第 5–6 週 | 收集、成就、終局、平衡、手機觸控區 |
| 7 | — | 先上 itch.io，反應好再進 GameDistribution / CrazyGames。**零伺服器依賴** |

## 三、10 個點子

### 1. 雪花球公司（Snow Globe Inc.）

搖雪花球，亮片落下變成金幣。核心動詞是拖曳搖晃＋粒子物理。幫手是球裡的小人偶，從內部幫你搖。進度軸是一排展示架，每顆新球是一個生態區、有各自掉寶表。Prestige = 球裂開，保留亮片。canvas 粒子成本低但畫面漂亮。

### 2. 討債模擬器

把 Bills Must Be Paid 反過來——你是討債的那一方。敲門、擊破藉口、收錢。張力機制是**名聲**：逼太緊整個街區不再開門，收入被掐住。幫手是越來越失控的合夥人。道德弧線給遊戲真正的結局。純 DOM，不需物理。

### 3. 堆肥點擊（Compost Clicker）

把廚餘變成土壤。步調慢、療癒。核心動詞是丟廚餘上堆，堆會肉眼可見長高變深。兩貨幣：體積（軟）／腐植質（硬）。幫手是蚯蚓、鼠婦、真菌——真實分解者、真實功能，升級樹能教東西。地層 = 挖自己堆出來的層理。美術便宜（軟塊狀 SVG）。

### 4. 電梯公司（Elevator Inc.）

一部電梯，無限樓層。乘客按樓層數付費，所以**進度軸本身就是錢**。張力在載客量 vs. 速度 vs. 耐性。幫手是額外電梯井。Prestige = 打掉重蓋更高的樓。

→ **[詳細設計見下方第四節](#四電梯公司詳細設計)**

### 5. 麵包發酵（Bread Rise Idle）

折疊麵團、等待發酵、烘烤、販售。妙處在**等待是機制而非懲罰**——發酵時間就是資源，升級買的是更好的發酵而非更快的點擊。幫手是有名字有情緒的酵頭（疏於照顧會死）。Prestige = 用保存的酵頭碎片養新的，保留「血統」加成。

### 6. 打水漂（Skipping Stones）

甩石過水面，每次彈跳就是收益。彈跳次數天生是指數獎勵，數值骨架白送。進度軸是湖擴張成海。收集品是 40+ 石頭，重量形狀改變甩擲手感。動詞極舒服，但也是最難調對的部分。

### 7. 垃圾信過濾（Spam Filter）

分類信件，點掉垃圾、留下真信。收入來自按正確分類計費的企業合約。張力：誤殺有代價，信件湧入快過你能讀。自動化 = 訓練過濾器（假的 ML 樹），主題完美契合，因為**自動化正是題材本身**。終局：過濾器產生自我意識。零美術預算。

### 8. 深海打撈

Dirt Clicker 的結構泡在水裡。潛艇往下穿越海洋層。**水壓是體力的對應物**——潛得比船殼耐壓深，可能失去本輪貨物，製造真正的「再下一層 vs 現在上浮」抉擇。幫手是遙控載具、受訓章魚。掉寶是 40+ 沉船文物附背景敘述。一張漸層背景就有高美術投報率。

### 9. 魯布・戈德堡公司（Rube Goldberg Ltd.）

每次「點擊」是把彈珠丟進裝置；彈珠觸發連鎖，鏈上每個元件都在乘算報酬。升級會實際在畫面加裝零件，所以**升級樹就是視覺本體**。這是「遊戲逐漸變成表演」最強的版本。做起來較難（需確定性連鎖模擬，非完整物理），但截圖與傳播天花板最高。

### 10. 房東帳本（Landlord's Ledger）

結構上最貼近 Bills Must Be Paid。繼承一間快垮的出租單位。租金月付、維修隨機、房貸是期限。錢的雙重用途張力完全成立：還債 vs. 整修。高利貸對應角色是掠奪性再融資業者。Prestige = 法拍，保留經驗點。加一條租客滿意度作第二軸避免淪為純算術。**十個裡最快做得出來**。

### 選擇建議

- **最快出貨**：4、7、10（無物理、無美術產線）
- **天花板最高**：6、9（但手感是生死線，先只做核心動詞原型）
- **辨識度最高**：3、5

## 四、電梯公司：詳細設計

> 一句話：你經營一棟不斷長高的大樓的垂直運輸，而大樓越高，你越忙不過來。

### 4.1 為什麼這個點子好

三個結構性優勢：

1. **進度軸就是收入軸。** 樓層數同時是「你走多遠了」和「你賺多少錢」。大多數增量遊戲得硬把這兩件事綁在一起（Dirt Clicker 的地層得額外配掉寶表才有意義），電梯天生就綁好了：票價 = 樓層差。
2. **張力是內建的，不是外掛的。** 樓越高，單趟收入越高，但**往返時間也越長**，低樓層乘客等到不耐煩就走人。這不是設計師硬塞的限制器（像體力條），而是從題材本身長出來的兩難。這種張力玩家會覺得公平。
3. **視覺天生適合手機直式。** 垂直捲動的井道剖面填滿螢幕，往上蓋的時候相機拉遠、樓變成一根細長的塔——這個「看著自己蓋的東西變高」的畫面本身就是獎勵。

### 4.2 核心循環

```
乘客在某樓生成（有目的地、耐性條）
  → 玩家/演算法決定電梯下一站
    → 電梯移動（加速 → 巡航 → 減速）
      → 開門、上下客
        → 收入 = 基礎票價 × |樓層差| × 乘客倍率 × 滿意度乘數
          → 花錢升級 → 樓變高 → 流量變大 → 回到開頭
```

### 4.3 核心動詞：手動調度

早期完全手動。畫面上顯示各樓等待中的小人偶（頭上有目的地標籤），玩家**點擊要去的樓層**來調度電梯。

這比純點擊有腦，因為玩家實際上在做取捨：先接 3 樓那三個上班族（近、便宜、快沒耐性），還是衝去 28 樓接那個 CEO（遠、超高單價、耐性極低）？

而且自動化的路徑非常乾淨：你買的不是「自動點擊器」，是**更好的調度演算法**。

### 4.4 體力的對應物：馬達過熱

按住空白鍵／長按讓電梯超速行駛（1.8×），但熱量累積。過熱就強制停機冷卻 8 秒，期間所有乘客耐性照跑。

這給了主動遊玩一個持續的、有風險的操作，對應 Bills Must Be Paid 的體力機制，但不會硬性結束一局。升級路線：散熱片 → 液冷 → 超導馬達（過熱機制最終被移除，這本身就是一個爽的里程碑）。

### 4.5 貨幣

| 貨幣 | 用途 | 是否跨 Prestige |
|---|---|---|
| **現金 $** | 一般升級：速度、載重、門、電梯井 | ✗ |
| **藍圖 📐** | 技能樹、樓層類型解鎖、地基等級 | ✓ |
| **評價 ★** | 不是貨幣，是**乘數**。滿意度累積成大樓評價，評價高 → 更高單價的租戶入住 → 所有票價 ×N | 部分保留 |

評價是這個設計的第二個聰明處：它讓「別讓乘客生氣」有長期複利價值，而不只是當下少賺一筆。

### 4.6 核心數值

電梯只有五個屬性，全部互相牽制：

| 屬性 | 影響 | 取捨 |
|---|---|---|
| 巡航速度 | 長程變快 | 對短程幾乎無幫助 |
| 加速度 | 短程變快 | 對長程幾乎無幫助 |
| 載客量 | 一趟載更多 | 但上下客時間變長 |
| 開關門時間 | 每站省秒數 | 站數多才有價值 |
| 電梯井數 | 平行處理 | 成本最貴，且需要調度演算法才發揮 |

**這五個屬性沒有一個是「全面更好」的**，所以升級選單永遠是真決策。這是 Bills Must Be Paid 的鎚子系統（高爆擊小範圍 vs. 高速大範圍低傷害）的同一招。

### 4.7 起始平衡（第一版）

```
起始狀態
  樓層數：10
  電梯井：1
  巡航速度：1.0 樓/秒
  加速度：0.5 樓/秒²
  載客量：4
  開關門：2.0 秒
  乘客生成：每 4 秒 1 位

經濟
  票價 = $1 × |樓層差| × 乘客倍率 × 評價乘數
  成本曲線 = base × 1.12^已購買數

前三個升級（教學用）
  +2 載客量        $50
  開關門 -0.4 秒    $80
  +5 層樓          $200   ← 第一次感受到「樓高 = 錢多」
```

第一次自動化（自動關門）應該在**遊玩約 6 分鐘**出現，第一個完整調度演算法在 **15 分鐘**。太晚玩家會累。

### 4.8 自動化階梯

這是遊戲的骨幹，也是最有梗的部分——因為電梯調度是**真實存在的電腦科學問題**：

1. **自動關門** — 最基本的解放
2. **FIFO 調度** — 誰先按誰先服務。笨，但你不用點了
3. **SCAN 演算法** — 電梯掃到頂再掃到底，不折返
4. **LOOK 演算法** — 掃到最遠請求就折返，不跑空段
5. **目的地控制（Destination Dispatch）** — 乘客在大廳先輸入目的地，系統分組。真實高樓技術
6. **群組控制** — 多井協同，不再各自為政
7. **快速電梯（Shuttle）** — 只停高樓層，不吃低樓流量
8. **雙層轎廂（Double-decker）** — 一次服務兩層
9. **空中大廳（Sky Lobby）** — 真實摩天樓設計，換乘節點，讓超高樓在數學上可行

玩家在解鎖第 3 個之後會發現：**這些演算法真的有效率差異**，而且遊戲有統計頁面能看出來（借 Dirt Clicker 的「誰在偷懶」）。

### 4.9 乘客類型（收集要素）

| 類型 | 票價 | 耐性 | 特性 |
|---|---|---|---|
| 上班族 | 低 | 低 | 量最大，尖峰時段暴增 |
| 觀光客 | 中 | 高 | 拍照，拖慢開門 2 秒 |
| 送貨員 | 高 | 中 | 佔 2 格空間 |
| 保全 | 無 | ∞ | 不付錢，但提升評價 |
| CEO | 極高 | 極低 | 要求專用電梯，讓他等會扣評價 |
| 貓 | 無 | 高 | 純提升評價。稀有 |
| 幽靈 | ??? | — | 只在 13 樓出現。稀有掉落 |
| 搬家公司 | 極高 | 低 | 塞滿整台電梯 |

目標約 20 種，配一本圖鑑。這是獨立於數字線之外的獎勵管道。

### 4.10 樓層類型（進度軸）

| 樓層 | 類型 | 解鎖的東西 |
|---|---|---|
| 1–10 | 零售 | 基礎流量 |
| 11–30 | 辦公 | 尖峰時段機制（早上 9 點暴衝） |
| 31–60 | 飯店 | 行李（載重機制）、夜間流量 |
| 61–100 | 住宅 | 常客、寵物 |
| 101–150 | 觀景台 | 觀光客潮 |
| 151+ | 實驗樓層 | 破壞平衡的東西 |
| 終局 | 屋頂 → 軌道 | 電梯衝出大氣層，遊戲結束 |

**結局很重要。** 參考的三款都是短遊戲，目標總時長 **4–6 小時**。

### 4.11 Prestige：打掉重蓋

觸發條件：蓋滿一定樓層或收入達標。

**保留**：藍圖、已解鎖樓層類型、乘客圖鑑、地基等級（= 新樓的基礎速度與最大高度）
**歸零**：現金、樓層數、所有現金升級

```
藍圖獲得量 ≈ floor( sqrt( 本輪總收入 / 1e6 ) )
```

主題上完美：拆一棟樓蓋更高的一棟，正是現實摩天樓的歷史。

技能樹三大分支：

- **機械**：速度、加速、載重、散熱
- **營運**：調度演算法、多井、群組控制
- **建築**：起始樓層、樓層類型、空中大廳

### 4.12 UI 與視覺

- **手機直式（主要）**：井道剖面填滿螢幕，升級用底部抽屜（swipe up）
- **桌機**：左側井道，右側升級面板
- 美術風格：扁平向量或像素，樓層有不同配色與家具剪影
- 乘客是小人偶，頭上有目的地數字標籤，耐性用頭頂細條表示（快沒耐性時變紅並晃動）
- **關鍵爽點**：每次增加樓層，相機平滑拉遠。玩到後期整棟樓縮成一根細塔，你能一眼看到自己蓋了多高
- 音效：叮！開門聲、樓層播報。這遊戲的音效設計空間很大且很便宜

### 4.13 技術注意事項

- 電梯運動是**簡單 1D 運動學**（等加速 → 巡航 → 等減速），不需要物理引擎。約 40 行程式碼
- 乘客是純物件陣列：`{ id, origin, dest, type, spawnTime, patience }`
- **最大的技術決策**：後期樓層數上百、乘客數上千，逐一模擬會爆。必須在中期切換成**統計流量模型**——高樓層不再逐個模擬乘客，改用「該區段每秒產生 N 元」的抽象。**這件事要在第 3 週前就決定好架構**，事後補很痛
- 離線收益：用平均流量 × 時間直接算，**不要重跑模擬**
- 存檔大小要注意：不要把乘客陣列存進 localStorage，只存統計數字

### 4.14 已知風險

| 風險 | 對策 |
|---|---|
| 手動調度太忙會累人 | 自動化提早，第一個演算法 15 分鐘內給 |
| 「進度軸就是錢」導致低樓層迅速失去價值，玩家只跑頂層 | 低樓層流量隨大樓高度**同步成長**（住戶都要經過大廳），並讓零售層有獨立的評價貢獻 |
| 五屬性互相牽制聽起來好，但可能算不出最佳解而讓玩家癱瘓 | 提供一個「效率」統計數字（每分鐘樓層數 × 載客率），讓玩家有可比較的單一指標 |
| 演算法梗太宅 | 每個演算法配一句白話說明 + 一個能看出差別的動畫示意 |

### 4.15 第一個原型該做什麼

**兩天內做完，只做這些：**

- 一個 10 層的井道，SVG 或 canvas
- 一部會動的電梯（加速度運動學）
- 點樓層 → 電梯過去 → 開門 → 上下客 → 加錢
- 乘客每 4 秒生成一個，頭上有目的地數字
- 一個計數器顯示 $

**驗證問題**：光是「點樓層、看電梯滑過去、叮一聲開門、錢跳出來」這件事，有沒有讓你想再點一次？

有的話，其他所有系統都值得做。沒有的話，問題在動詞的手感（速度曲線、音效、開門動畫），先修那個，不要急著加升級。
