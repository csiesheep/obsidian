# 鬼故事產生器

> [!info] 一句話
> 從鬼故事來源抽「結構」和「評分」而不是抄文本；用加權抽樣規劃骨架，LLM 寫，LLM 評審，不及格就改。目標是讓 marvel 板老鄉民推「雞皮疙瘩」而不是「虛」。

## 核心主張

- 來源最值錢的不是故事本身，是**結構**和**評分**。直接 fine-tune 或檢索原文會做出抄襲機，而且不會更可怕。
- 「好」是評審撐出來的，不是語料量撐出來的。PTT 推噓文是免費的品質標籤。
- 可怕靠真實感，不靠鬼。鬼越清楚越不可怕；結尾收太乾淨也不可怕。這兩條要寫進評審規則。

## 第一版範圍（2026-10-13 定案）

PTT marvel 板 `[經驗]` 文、推文數 ≥ 30、約 200 篇。微疼等口述來源留到第二版。

## 管線

```
collect   PTT 站內搜尋 recommend:30 → 逐篇抓本文和推噓
annotate  LLM 把每篇拆成故事 DNA
stats     哪些組合高分、高分組節拍比例、字數、鬼露出 → weights.json + report.md
generate  規劃器抽骨架 → 寫手 → 評審 → 不過就照意見改，最多三輪
```

程式目前在 Claude Code session 裡（Python，`ghost/` 套件 + `prompts/` 三份 prompt），還沒搬進 repo。

### 故事 DNA 欄位

| 欄位 | 內容 |
|---|---|
| 場景 | 20 種：宿舍、當兵、夜班、山路、租屋、醫院、超商、老家、校園、飯店、夜路、喪事、廟宇、辦公室、大眾運輸、童年家中、電梯樓梯間、國外、水域、其他 |
| 恐怖機制 | 13 種：身份錯置、時間錯亂、逐步失控、犯禁忌、事後才知道、見證不一致、重複循環、在場感、善意型、附身、物件作祟、夢境滲入、只有聲音 |
| 結尾 | 開放、有解釋、反轉、淡出 |
| 節拍 | 正常、小異常、否認、升級、揭露、餘波，各佔比例 |
| 鬼露出 | 0 沒正面寫、1 間接跡象、2 一瞬間看見、3 清楚描述 |
| 錨點 | 讓它像真的細節類型（門禁時間、值班交接簿） |
| 聲音標記 | 第一人稱、朋友的朋友、免責開頭、鄉民用語、AI 潤飾、具體地點、具體時間、程序細節、對話、自我懷疑 |

### 權重公式

`weight = mean_score × ln(1 + n)`。高分但只出現一次的類別不會壓過常見又穩定高分的。場景 × 機制的條件抽樣只在同組合至少兩篇時啟用。

### 模型

annotate 用 Haiku（批量抽取，便宜），write 和 judge 用 Opus。三種憑證都能跑：API key、`ant auth login`、或 Claude Code 訂閱走 `claude -p`。

## 第一輪結果（2026-10-13）

**資料**：抓了 201 篇（2023 到 2026，推文中位數 54，46 篇爆）。因為這台機器沒有 API 憑證，先用 Claude 子代理照 annotate prompt 手標 60 篇當種子，38 篇可用（其他是系列中段、回文、翻譯文）。

**詞彙表被真資料改掉的地方**：加了場景 `home`（自家）、`ruins`（廢墟），機制 `dead_contact`（亡者來電）、`proxy_sighting`（透過通靈者看見），聲音標記 `translated`（預設納入，`stats --exclude-translated` 可排除；10-13 使用者決定翻譯文也要用）。抓取改成跳過 `Re:`。

**38 篇看到的訊號（樣本小，是假設不是結論）**：

| 指標 | 高分組（爆） | 低分組 |
|---|---|---|
| 轉述家人朋友的事 | 0.61 | 0.30 |
| 免責開頭 | 0.44 | 0.10 |
| 日常程序細節 | 0.33 | 0.80 |
| 鄉民用語 | 0.33 | 0.70 |
| 鬼露出平均（0 到 3） | 2.3 | 2.1 |

主要機制依權重：附身、事後才知道、物件作祟、身份錯置。結尾：開放和有解釋並列第一。

> [!warning] 推文數獎勵的不是「小而真」
> 原本的假設是「鬼越清楚越不可怕、事件越小越可信」。爆文的資料相反：大事件、轉述、鬼露出高。推文數量的是戲劇性和轉述感。prompt 已改成跟著規劃器從資料抽出的參數走，不另設絕對規則。但「推文數 = 好」本身值得再想：如果目標是「像真的」，可能要另找訊號（例如推文裡「雞皮疙瘩」「毛」的比例，而不是推文總數）。

**兩篇樣本**：用同一套 prompt、規劃器抽出的骨架，由子代理當寫手和評審各跑一輪。seed 7「我弟收驚那一晚」（廟宇、附身、開放、鬼露出上限 1）總分 9；seed 42「跟我姊合租的那半年」（租屋、附身加事後才知道、反轉、上限 2）總分 9。評審的修改意見都是段落級的連戲問題（夜班時間矛盾、暗客廳怎麼看到人、沙發半年不會塌、連續短句收尾太整齊）。

**要小心的地方**：寫手和評審是同一家模型，兩篇都一輪過，可能是評審偏鬆。校評審最便宜的做法是拿 10 篇真實爆文和 10 篇真實低分文餵給它，看分得開分不開。

## 法律

只抽結構欄位，`annotated.jsonl` 和 `weights.json` 不含原文句子。`raw/` 只留本機（已 gitignore），不重發、不拿去訓練會吐原文的模型。

## 標註模型比較（2026-10-13）

同樣 60 篇種子，經 Claude Code CLI 跑 Haiku 5.5 和 Sonnet 5.5（effort medium、4 路平行），跟子代理手標的種子比。完整表格在程式資料夾的 `data/compare.md`。

| 指標 | Haiku 5.5 | Sonnet 5.5 |
|---|---|---|
| 場景跟種子一致 | 65%（κ 0.62） | 77%（κ 0.74） |
| 結尾跟種子一致 | 47%（κ 0.18） | 70%（κ 0.57） |
| 主要機制跟種子一致 | 35% | 49% |
| 結尾判成「開放」 | 35/45 | 19/46（種子 16/43） |
| 主要機制判成「在場感」 | 18/45 | 8/46 |
| 一句話前提 ≤ 30 字 | 72% | 0%（多寫成 35 到 45 字，內容比較完整） |
| 每篇耗時 | 11.4 秒 | 9.1 秒 |
| 每篇定價成本 | $0.0021 | $0.033 |
| 7000 篇定價成本 | 約 $15 | 約 $231 |

**結論：用 Sonnet 5.5。** Haiku 有系統性偏差，結尾八成判開放、機制四成判在場感，這會直接把規劃器抽出的骨架扭成「開放結尾 + 在場感」，而在場感在種子裡是低分機制。讀原文判五篇結尾分歧：Haiku 錯 2 到 3 篇，Sonnet 錯 2 篇，種子大致對。Sonnet 也不完美，會把「事情被處理掉」當成「有解釋」。

**額度**：兩個模型各 60 篇，週額度都停在 22% 沒動，五小時額度只動 1%（含主 session）。量太小看不出比例，要跑到幾百篇才量得到。

**CLI 的成本數字不可信**：Claude Code CLI 的價目表沒有 Haiku 5.5（costBasis=unknown），回報的成本高了約 100 倍。程式改成照 token 數和官方定價自己算，Sonnet 的數字跟 CLI 完全對得上。

### prompt v2 與 Opus 5.5（同日稍晚）

prompt v2 改了：標註輸入拿掉推文分數和推文（統計要算欄位跟分數的關係，標註者不能先看到分數）；補結尾、主要機制、場景、is_story、鬼露出的判定規則和例子；錨點加好壞例子；長度放寬（場景 30、最可怕一刻 40、前提 45 字）。每筆紀錄帶 `prompt_version`。

| 指標 | Sonnet 5.5 v1 | Sonnet 5.5 v2 | Opus 5.5 v2 |
|---|---|---|---|
| 結尾跟種子一致 | 70% | 65% | 74% |
| 主要機制跟種子一致 | 49% | 37% | 56% |
| 結尾分布（開放／有解釋／反轉／淡出） | 19/16/4/7 | 12/18/6/9 | 16/15/8/6（種子 16/13/8/6） |
| 跟三方共識：場景／結尾／機制 | 75/76/56% | 93/88/74% | 88/97/90% |
| 讀原文判的五篇結尾 | 2/5 | 3/5 | 3/5（種子 5/5） |
| 長度規則全過 | 否 | 否（前提 68%） | 是 |
| 每篇定價成本 | $0.033 | $0.029 | $0.058 |

三方共識是種子、Sonnet v2、Opus v2 的多數決，三者都是投票者，所以它們自己的數字偏高，拿來比 v1 和 Haiku 比較公平。場景定義改成「最可怕那一幕發生的地方」之後，種子的場景已經不符新定義，場景一致率不能再拿種子當參考。

**結論改成 Opus 5.5。** 機制和結尾的分布最接近種子、跟其他標註者最一致、長度規則全守。代價是 Sonnet 的兩倍。prompt v2 對 Sonnet 是好壞參半，結尾和機制跟種子的一致率反而掉了，鬼露出也被推高（31/45 篇給 3）。

**不要混用模型。** 統計是在比高分組和低分組，如果高分組用 Opus、低分組用 Sonnet，差異會有一部分是標註者造成的。全量只能選一個模型。

**額度**：Sonnet v2 加 Opus v2 共 120 篇，定價合計約 $5.2，週額度從 22% 到 23%（含主 session）。一格太粗，只能說 1% 大約對應幾美元的量級。照這個量級，Opus 標 7000 篇（約 $405）可能吃掉一整週以上；標 2700 篇（夠 2000 篇可用，約 $156）比較實際。先跑 300 篇看週額度動多少再決定。

### Opus 5.5 全標 201 篇（同日）

抓到的 201 篇全部用 Opus 5.5 + prompt v2 標完，180 篇判為可用故事（新規則把合集和能獨立讀的系列章節也算進來）。這份現在是正式標註，`stats` 預設讀它；種子改名 `annotated.seed.jsonl` 留作參考。

額度實測：141 篇、定價約 $7.5，五小時額度從 0% 到 3%（剛重置，含主 session），週額度停在 23%。換算一個五小時窗口大約夠標三四千篇；週額度 1% 大約對應 $5 到 $15，所以 7000 篇（約 $383）可能吃掉週額度的兩成五到七成五。4 路平行每篇有效約 2.5 秒，7000 篇約 5 小時。

## 毛率、規則 v2、評審校準、新舊對照（2026-10-14 晚）

**毛率**（`data/scare_report.md`）：推文裡「好毛、雞皮疙瘩、可怕……」的比例。推文百分位跟毛率的等級相關只有 +0.08（經驗）、+0.04（翻譯），跟虛率反而 +0.15：受歡迎不等於可怕。兩個訊號都支持的：鬼清楚露面、鬼別完全不露面、具體地點、對話（翻譯文）。有解釋的結尾推文多但毛率低、虛率高；反轉結尾推文少但毛率高；程序細節兩種文章方向相反。

**規則 v2**（舊版存 `prompts/v1/`，`generate --rules v1|v2` 切換）：寫手要有對話、地點時間具體、露出上限也是目標、最可怕那一幕語氣篤定；拿掉「寧可寫我沒有回頭」「留一兩處不確定」「程序寫一堆是毛病」「六成是轉述」；免責開頭改可選。評審的「鬼的克制」改成「鬼的處理」：上限允許卻含糊帶過扣分；示範修改意見改成要寫出看到什麼；explained 結尾由別人說出就不算太乾淨。評審看到的 schema 說明也改成中性。

**評審校準**（真實經驗文高分 20、低分 20，`data/calibration.jsonl`）：兩版評審都分不出真實的高低分文章。總分 AUC v1 0.57、v2 0.51（0.5 是瞎猜）；真實爆文的通過率只有 v1 45%、v2 25%。分數擠在 6 到 7。v2 的子項有點訊號：鋪陳 AUC 0.74、鬼的處理 0.62（v1 是 0.48）。結論：評審檢查的是「有沒有照規則」，不是「讀者喜不喜歡」，通過門檻目前跟真實品質無關。

**新舊對照**（10 副同樣的骨架，`data/ab/`）：v2 確實照設計改變寫法：引號對話從平均 6.4 段變 10.6 段、作者自我懷疑從 9/10 篇降到 5/10、結尾照骨架從 5/10 升到 8/10、鬼寫到上限 10/10（v1 也有 9/10）。但兩版評審交叉打分幾乎打平（逐對比 15 次平手、3 次 v1 贏、2 次 v2 贏）。評審分不出好壞，所以要靠人讀：盲讀檔在 `data/ab/blind/`，答案在 `key.json`。

**兩兩比較評審**（`prompts/pairwise_judge.md`、`ghost/pairwise.py`，結果 `data/pairwise_calibration.md`）：一次給兩篇，問哪篇推文多、哪篇比較毛。用真實配對測，每對 A、B 對調各判一次：
- 熱門度配對（同年前 10% vs 對照組後 30%，40 對）：判推文多選對 91%（95% 區間 85% 到 97%）
- 可怕度配對（推文百分位都約 0.8、毛率 17.9% vs 0.3%，30 對）：判比較毛選對 93%（87% 到 100%）
- 它分得出熱門和可怕：可怕度配對裡判「推文多」只有 52%（兩篇推文本來就差不多，該是瞎猜）
- 對調後九成以上不變，選 A 51%，沒有位置偏好；信心 2/3/4 分別選對 79%/94%/98%
- 舊的絕對分數評審同類測試只有 AUC 0.51 到 0.57

注意：這些是公開的 PTT 文章，模型可能在訓練時看過，準確率可能有一部分是記憶。要用模型訓練截止（2026 年 6 月）之後的文章再驗一次。

新舊對照的 10 對也用它判過了，結果封存在 `data/ab/pairwise.jsonl`，等盲讀完再看（`py -m ghost.ab_pairwise --reveal`）。

盲讀網頁：https://claude.ai/artifact/PUCTypUy4dSrS4UY4dnM4C（選擇存在網頁的資料庫 `votes` 集合）。

**盲讀結果（10-15）**：我（使用者）舊規則勝 4、新規則勝 3、平手 3；兩兩評審（毛）新規則勝 8、舊 1、分歧 1。雙方都有選邊的 6 對只一致 2 對。分歧的 4 對，評審形容舊版「節制、留白精緻、收斂、偏溫情安靜」，新版「畫面直接、持續惡化、正面撞鬼」：我偏好克制留白，PTT 讀者資料和評審偏好直接。另外我 7 次選邊有 6 次選 A，A 剛好 7/10 是舊版，可能有位置偏差。選擇存在 `data/ab/blind/user_votes.json`。下次盲讀：A、B 版本各半，改成一次讀一篇各自打分。

**決定：兩種口味都留**，`generate --taste 直接|留白`，預設直接。留白不是舊規則：它保留 v2 被資料支持的改進（要有對話、地點具體、拿掉錯的說法），只把鬼和語氣換回克制（上限內留白、寧可寫我沒有回頭、可以留一點不確定、評審獎勵留白、簡約風格的最可怕那一幕省著寫）。規則在 `prompts/restrained/`。示範：同一副骨架（宿舍、附身加逐步失控、反轉、上限 3、短篇）在 `data/out/taste_demo/`：直接版寫出「只有眼白、頭歪到不對的角度、指節白掉」；留白版靠鐵梯的聲音、床架晃、聽不懂的台語，最後一句反轉才揭露。兩篇評審都給 8 分。

故事 793 個的分布：結尾開放 40%、反轉 25%、有解釋 22%、淡出 12%；鬼露出 3 佔 48%、1 佔 34%；場景前三是自家、夜路、租屋；主要機制前三是事後才知道、在場感、身份錯置。翻譯文的反轉結尾特別多（91/215）。

**發現並修掉的資料問題**：2007 年前的舊格式文章沒有標題欄，作者、標題、時間混在本文開頭，共 563 篇標題空白（多數在早期和精華區）。解析器改成從本文讀出表頭；讀不到的從索引補；原文已修補（備份在 `data/raw_backup_*`）。修補時一度把 1181 篇翻譯文開頭的「原文標題：」誤當表頭刪掉，已從備份還原，規則改成作者和標題兩行都要有才算。修完系列多合出 5 組，語料 9395 個單位。56 個空標題標過的單位重標：故事判斷全部不變，但結尾改了 15 個，顯示結尾這欄本身就不太穩定。

**補 2007 年以前（10-14）**：`[經驗]` 標籤 2007 年才流行，之前用 `[真實]`，2003 到 2005 年連標籤都沒有；早期推文也很少，推文門檻會全擋。補法：

- 看板列表頁 index1 到 index190（2003-02 到 2006-12）：3779 篇，大多是連載小說（天使、種字傳說、黑色微波、霏小說……）。標題規則：有標籤只收真實、經驗；沒標籤的去掉章節編號、小說轉載字眼、同作者同標題 5 篇以上，剩 775 篇（其中真實標籤 222 篇跟搜尋重疊）。剩下的還混小說、新聞、問答，交給標註判。
- prompt v2.1：is_story 加「小說形式的創作、新聞、知識介紹、問題算 false；親身口吻（含 NoSleep 翻譯）照常判」。
- 這兩塊標 `sample: unfiltered`，存 `ptt_marvel_early.jsonl`，沒有推文訊號，統計時只能用精華區旗標或不參與高低分比較。

**年份很不平均**：`[經驗]` 推 ≥ 30 有一半在 2015 到 2018 年，2023 年後一年只剩幾十篇。早期和近年推文習慣不同，統計的高分組要改成同年份內的百分位，不能直接比推文數。最早那 201 篇幾乎全是 2023 年後的，只代表近年板風。

## 2000 篇抓取計畫（2026-10-13 擬）

目標：2000 篇**可用**（進統計）的故事。目前可用率 63%（60 標 38 用），加上系列合併和跳過 Re: 估可到 75%，所以要抓 2700 篇以上原文。

### 存量（今天探過）

| 來源 | 存量 | 怎麼知道的 |
|---|---|---|
| PTT marvel `經驗` 推 ≥ 50 | 2000 到 3000 篇 | 搜尋第 100 頁滿、150 頁空 |
| PTT marvel `經驗` 推 ≥ 30 | 4400 到 5600 篇 | 第 220 頁滿、280 頁空 |
| PTT marvel `經驗` 推 ≥ 20 | 5000 到 7000 篇 | 第 250 頁滿、350 頁空 |
| PTT marvel `經驗` 全部 | 14500 到 16000 篇 | 第 725 頁滿、800 頁空 |
| PTT 精華區 經驗區 | 估 1000 到 2000 條 | 新版 19 類 + 舊版 13 類，山上／郊區一類 86 條 |
| Dcard 靈異版 | 0 | curl 403；內建瀏覽器也遇到 Cloudflare 人類驗證，不繞 |
| 微疼、偷聽 story | 未探 | yt-dlp 沒裝；留第二階段 |

結論：PTT 推 ≥ 30 全抓就超過目標，不需要 Dcard。

### 步驟

1. **建索引（15 分鐘，免費）**。只翻搜尋列表頁不抓本文：`經驗` 全部約 750 頁，每頁 20 條，拿到 15000 條的標題、作者、推文數、連結。有了索引才能挑，也能算「推文數分布」當背景。
2. **抓本文（約 4 小時背景跑，免費）**。從索引挑推 ≥ 30 的全部（約 5000 篇）加上隨機 500 篇推 < 10 的當對照組。對照組很重要：現在的「低分組」其實是推 30 到 50，不是真的低分，評審校不準。間隔 1.5 秒、單執行緒、可續抓。
3. **精華區（約 1 小時，免費）**。遞迴抓 `/man/marvel/DFB6`（新版經驗區）和 `/man/marvel/D2C`（舊版）。沒有推文數，給 `curated` 旗標當品質訊號；舊文有 ANSI 色碼要剝掉。
4. **合併系列、去重**。同作者且標題帶 (一)(二)、上中下、之一之二的接成一篇；同作者 30 天內的 `Re:` 當續章。五字 shingle 做近似去重（精華區和板上會重複、經典文會被轉貼）。這一步讓「亡母來電」那種 11 章變 1 篇可用。
5. **標註（30 到 60 分鐘，約 5 美元）**。Haiku 平行 8 路，或走 Batch API 半價。7000 篇 × 3k token。
6. **統計改三件事**：分數改成源內百分位（推文數和精華區旗標才能放一起）；加推文關鍵字比例（雞皮疙瘩、毛、可怕 vs 虛、無聊）當第二個品質訊號；對照組進低分組。
7. **第二階段（半天，約 1 美元）**：裝 yt-dlp，列微疼和偷聽 story 的影片，抓 zh-TW 自動字幕，LLM 切段成單篇故事，標 `oral`。目標 300 到 500 篇，拿口述節奏，不混進文字統計。

### 預期產出

推 ≥ 30 約 5000 篇 × 0.75 ≈ 3700 可用，精華區 1500 × 0.9 ≈ 1300，合計 5000 篇上下，是目標的兩倍半。可以把「品質核心」定在推 ≥ 50 的 2000 到 3000 篇，其餘當分布背景。

### 要改的程式

collect 加索引模式和從索引抓；新 collect_digest；merge_series；dedupe；annotate 平行化；stats 百分位和推文關鍵字。約半天工。

### 風險

PTT 可能回 429，已有退避；精華區格式老，解析要另寫；標註模型換了（子代理手標 vs Haiku）分布可能飄，種子 60 篇留著當校準用。
