# 所有 API 都回同一行字：error code: 1101

## Threads
### 1
我的遊戲網站有幾分鐘，每個資料請求都只回一行英文：

error code: 1101

然後它自己好了。
根因，到今天還沒查到。

《蓋牌投票箱》是把候選人名字蓋起來、只看政見猜是誰的網頁小遊戲。10/22 深夜，AI 在查統計時發現：統計、遮蔽健康度（檢查名字有沒有真的蓋住）……查到的 /api/ 網址都壞了，網頁本身還開得了。

自己好的 bug，最可怕 👇
![[38/01.jpg]]
### 2
Cloudflare 的說明：1101 通常是 Worker（跑在 Cloudflare 上的那段伺服器程式）執行時丟出一個錯，沒有人接住。

Cloudflare 只好回一頁錯誤，不是遊戲看得懂的資料。
翻程式一看，Worker 入口一個 try/catch 都沒有 orz

開單時寫下的猜測是：資料庫（D1）暫時失敗或逾時。
很合理，對吧？
接單的 AI 看完，只回了一句：這個猜測說不通。
![[38/02.jpg]]
### 3
為什麼？壞掉的網址裡，有一個是桃園的遮蔽健康度。桃園還沒收錄任何政見段落，那個請求要讀的東西是空的——一次都不碰資料庫。

它在本機接一個空的資料庫試：
・台北統計 → 500，還把錯誤和 stack trace 原樣吐給使用者
・桃園健康度 → 200，正常

資料庫壞了，桃園照樣會好。線上桃園卻也 1101，錯就不在資料庫那段。
再查：那時也沒有在部署，上一次部署是好幾個小時前。
![[38/03.jpg]]
### 4
根因不知道，先把傷口包好。

① 任何例外都回 503 和一小段 JSON：{"error":"unavailable"}。不再把錯誤內容吐給使用者。
② log 也要遮：只印一行錯誤類別和訊息，先遮掉 IP、段落編號、候選人的名字。錯誤訊息裡什麼都可能有，我不想讓 log 變成另一個外洩的地方。

前端也查過：送出一局結果時遇到 503，就安靜跳過，那一局不計；健康度頁會顯示錯誤訊息。
![[38/04.jpg]]
### 5
③ 壞的時候，不能寫一半。

一局要加好幾個計數。舊程式留了一條退路：沒有「一次寫完」的功能時，就一筆一筆加。萬一走到那條路，第二筆失敗時第一筆已經寫進去了，玩家卻拿到「錯誤」。

現在一局的所有計數一次寫進去（D1 batch，一個交易），全成功或全不算，退路直接拿掉。
剩一個縫：交易寫完、回應才失敗，那一局會算到，玩家卻看到錯誤。
前端一局只送一次，所以也不會重送、算兩次。
![[38/05.jpg]]
### 6
怎麼證明它有用？

先做一個會壞的資料庫：每次讀寫都丟錯，錯誤訊息還故意夾一個 IP 和一位候選人的名字。
舊程式跑 10 條：3 過 7 紅，7 條都印「丟出例外（就是 1101）」。改完再加一條測入口那層，11 條全過。

再做 5 次證偽，一次只拿掉一個保護：拿掉 catch、改回一筆一筆寫、log 全不遮、只不遮名字、拿掉入口那層。每一次都有測試變紅。
GitHub 上開單到關單（含部署）7 分鐘。
![[38/06.jpg]]
### 7
老實說：根因還沒查到，要看 Cloudflare 後台那幾分鐘的 log。這次接得住程式裡丟出的錯；如果是 Worker 本身沒起來、或 Cloudflare 那邊出錯，它擋不住，還是會 1101。做 Workers 遇過的朋友，有錯請指正 :p

學到的事：開單時寫下的猜測，不是事實。
最便宜的檢查，是找一個「照猜測不該壞、卻也壞了」的例子。桃園那一個請求，就把猜測推翻了。
